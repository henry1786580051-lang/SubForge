# 有词时间依据的边界修复

本次实现覆盖英文源字幕的局部结构依赖，不代表通用句法分析器，也不把风险分数为零解释为句子完整。主要处理修饰语与中心词、插入语打断的谓语、重复起句、车型标识等跨字幕依赖。

## 新任务的处理顺序

断句 → LLM 清理 → 原词映射和局部边界修复 → 翻译及既有译文复核。

`structural.py` 输出依赖类型及左右证据。新结构依赖的候选切点必须有标点或受限连词分句依据，同时通过现有边界风险检查。只允许移动原始词边界；时长为 0.6–8 秒，词数服从用户设置。不能找到安全切点时保留字幕并报告未解决依赖。新规则不会把说话人冲突推断为分离错误。

`mapped_boundary.py` 将清理后的词投影到原始词时间。支持大小写、标点变化、有限语气词删除及相邻重复词删除。任意词替换、无法对应的删除、估算时间、重叠时间及混合说话人均不参与自动重排。没有实现任意改写或数字读法转换的强制对齐。

原始词及其元数据保留，即便某个语气词不再显示。重建后检查完整词序，避免清理丢词；保留不受影响字幕的原始显示时间。车型名称可以读取全文重复证据，但修复区域仍被停顿、说话人和映射失败隔开。

## 已有双语文件

`bilingual_repair.py` 把源文、边界时间和译文作为一次提交。最多处理三个原字幕组成的窗口；译文缺失、校验失败或模型异常时整窗恢复原稿。取消信号继续向上传递。默认最多尝试 32 个修复窗口，不自动重试失败窗口。

开发工具 `scripts/repair_subtitle_boundaries.py` 要求原始词级 SRT、中文在上的双语 SRT 和一个不存在的输出目录。默认只生成本地诊断；`--glm` 启用窗口重译及独立验证；`--full-review` 对最终整片字幕进行重叠窗口复核。原始文件不会覆盖。重译与验证都携带相邻只读上下文，避免将音响功率误解为车辆动力，但禁止借用邻条事实。

复用记录时必须匹配模型、提示词哈希、操作类型及完整输入。复用不计入新 token 消耗，原始运行记录保留。全量复核中的模型意见是候选问题，不是人工确认的错误率或音频核验结果。

## 验证边界

本地检测和映射不调用 LLM；新增强依赖复用现有翻译复核流程。不能据此声称总 token 消耗一定不变。整片模型评估是开发验证开销，不会新增到每次正常任务。

测试覆盖实际 47/48 边界、清理后的车型名称、原始语气词保留、重复运行稳定性、说话人冲突、时长/词数限制、事务回滚和调用预算。历史文件的全量复核不等同于重新运行 ASR 或整条生产翻译流程。
